# 分批建仓跟踪（Position Tracker）

工作台第一张卡「分批建仓」→ 点标题/「全部」进入建仓视图（列表 → 详情）。数据全部落在 Vault 的 Markdown 里，重启不丢、手改可读。

## 1. 文件布局

```
Finance/Investment/Accumulation/
  plans/     600519-pl_7f3k2m9q.md      ← 每个计划一个文件
  archive/   00700-pl_tencent1.md       ← 归档后移到这里
```

- 目录由设置项「建仓数据文件夹」决定，默认 `Finance/Investment/Accumulation`，**与年度数据文件夹互相独立**。
- 文件名固定 `{symbol}-{id}.md`：同一标的多轮建仓不会互相覆盖；纯 id 会让文件树里认不出标的。
- 插件创建后不会自动改名。归档 = 写 `archivedAt` + 文件移到 `archive/`。

## 2. 文件格式

frontmatter 只支持**扁平 `key: value`**（没有嵌套、列表、块标量、锚点）。写了不支持的语法，插件会把文件判为「解析失败」并**冻结写入**——宁可报错，也不静默丢内容。

```markdown
---
id: pl_7f3k2m9q
name: 贵州茅台
symbol: 600519
market: CN            # CN | HK | US | OTHER
assetType: stock      # stock | etf | fund | bond | other
currency: CNY         # CNY | HKD | USD
createdAt: 2026-09-01
updatedAt: 2026-11-03T06:20:11.000Z
totalBudget: 125000.00
referencePrice: 1500
currentPrice: 1290.88
priceUpdatedAt: 2026-11-03
reserveRatio: 0
amountMode: custom    # fixed | ladder | custom
requireConfirmDefault: true
---

# Stages
| Order | Label | Kind | Mode | Anchor | Drop% | Target | Trigger | Planned | Confirm | ConfirmedAt | SkippedAt | SkipReason | VoidedAt |
```

四张表：`# Stages` / `# Trades` / `# Prices` / `# Adjustments`；两段正文：`# Investment Thesis` / `# Review`。
分节标题中英文都认，写回时统一用英文（与 `Finance/Misc.md` 的习惯一致）。

### 金额与日期

- 金额固定 2 位小数、**不带千位分隔符**、不写币种符号（币种在 frontmatter）。
- 价格最多 4 位、去尾零；数量最多 6 位。
- 百分比字段不带 `%`（列名带）；日期一律 `YYYY-MM-DD`。

### 手改这几条要知道

| 位置 | 归属 | 行为 |
|---|---|---|
| frontmatter 已知键 | 插件 | 每次保存全量重写 |
| frontmatter 未知键 | 你 | 原样保留（可以加自己的元数据） |
| 四张表 | 插件 | 保存时重排、补格式；解析不了的行原样留在表尾 |
| `# Investment Thesis` / `# Review` | 你 | 逐行原样保留，插件只读不改 |
| 其它 `#` 分节 | 你 | 整段原样保留，跟在文末 |

- **`Trigger` 列是只读派生列**：读入时忽略你手写的值，永远按 `锚定价 × (1 − 跌幅%)`（或 `Target` 目标价）重算。想改触发价，改 `Drop%` 或 `Target`。
- **触发价锚定在 `referencePrice`**：之后无论成交价怎么变，触发价都不漂移。
- 单元格里的 `|` 要写成 `\|`，否则整行会被切错列。
- `# Prices` 同一天只留一个点，后写的覆盖先写的。

## 3. 计算口径

金额一律用整数「分」运算，只在读入和写盘两个边界取整，避免 `47 × 1290.88 = 60671.36000000001` 这种尾巴落进文件。

| 指标 | 口径 |
|---|---|
| 累计投入 | Σ(买入金额 + 买入手续费) − Σ(卖出金额 − 卖出手续费)，即净现金占用 |
| 持仓数量 | 买入数量 − 卖出数量 |
| 持仓成本 | 移动加权平均；卖出时按数量比例转出成本（唯一取整点），清仓残差并入已实现盈亏 |
| 持仓均价 | 持仓成本 ÷ 持仓数量 |
| 持仓市值 | 持仓数量 × 当前价（未录价时不算市值，也不假装浮亏 100%） |
| 浮动盈亏 | 市值 − 持仓成本；比例的分母是持仓成本 |
| 剩余预算 | 计划总预算 − 累计投入（可为负，负值用警示色标超投） |
| 预算使用率 | 累计投入 ÷ 计划总预算 |
| 预留资金 | 总预算 × `reserveRatio`，不参与阶段分配 |

**阶段状态是算出来的，不是存下来的**：文件里只有 `SkippedAt`、`VoidedAt`、`ConfirmedAt` 三个用户意图标记，`待执行 / 已触发 / 部分执行 / 已完成` 全部由「成交 + 现价 + 触发价」现场推导。成交是唯一事实源，所以改计划不会覆盖历史，删一笔成交状态也会跟着回退。

优先级：`已失效` > `已跳过` > `已完成`（实际 ≥ 计划）> `部分执行` > `已触发` > `待执行`。

**右侧确认阶段只看 `ConfirmedAt`**：价格涨过确认位不会自动触发，必须手动「标记已确认」。左侧阶段全部了结之前，它也不会出现在「下一次建仓」里。

**下一次建仓**取第一个未了结的阶段，给出触发价、当前价、距触发（低于/高于百分比）、计划金额、剩余预算。触发只代表「价格条件满足」，不等于该买——是否执行、是否调金额、是否跳过，都在详情页手动决定。

**最大浮亏/浮盈**按 `# Prices` 的每个价格点、以当日持仓成本为基准算浮动收益率。价格点少于 2 个时显示「数据不完整」，不会拿 0 充数。

## 4. 多币种

- 计划内所有金额按本币存储与展示，列表里每行带币种后缀。
- 跨计划汇总（卡片合计、列表排序、第二批复盘）优先用 `Finance/Misc.md` 里持仓行情写入的 `fxRate`（`CNY per 1 unit`），读不到再回落设置项「参考汇率」，最后兜底 1。
- 单计划可用 frontmatter `fxRateOverride` 覆盖。

## 5. 容错与并发

- 解析失败的计划文件不会出现在列表里，而是在列表下方列出路径，点开直接看原文；此时它的编辑入口全部禁用。
- 写盘用 `adapter.process` 原子替换（旧版本没有该方法时退回 `write`）。
- 同一计划的读改写串行排队；写盘前若发现磁盘内容与上次写入不同，会先把磁盘内容读回来，再叠加本次改动——你刚手改的表格不会被插件的旧内存覆盖。
- 写完盘会收到 `modify` 事件，插件用内容 hash 判定「这是我自己写的」并吞掉，不会触发重解析抖动。
